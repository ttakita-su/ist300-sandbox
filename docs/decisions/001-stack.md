**Context:** The V1 trainer (F1–F4; MVP slice S11 → S1 → S2 → S3, plus S4 and S5) has to start a first hand within 60 seconds with no install and no account (PRD §5.2 L111, §6.1 L127, L132), keep history with no backend (§6.1 L133), and share one strategy file with the V1.1 Chrome extension (§6.1 L134, F9 L263). I also know plain HTML and JavaScript much better than React or Firebase.
**Decision:** Plain HTML, CSS and JavaScript with no framework, no build step and no dependencies: one page (`free-bet/index.html`) plus one shared classic script (`free-bet/extension/strategy.js` with `Strategy` and `Engine`), served as static files by GitHub Pages from `main`, with history in browser `localStorage` (`freebet.history.v1`, `freebet.primer.v1`) and tests run by `node free-bet/tests.cjs`.
**Why not the alternative:** React + Firebase (Hosting, Firestore, Auth) solves problems V1 does not have: accounts are ruled out (§6.1 L132, S5, W6), the PRD says no backend is needed (§6.1 L133), and Firestore sync is network traffic the extension must not make (F9 L264), so the shared strategy file would still have to stay a plain script while the trainer gained a bundler, an SDK and a cloud project to configure; on the one criterion that is about me rather than the product, I am more fluent in plain JavaScript, so I can finish V1 sooner.
**What it costs:** History lives in one browser on one device, has no size cap or clear/export control and is lost if site data is cleared; there is no server, so §5.2 metrics such as session completion cannot be collected centrally; the page is one 70-line file with dense inline CSS and script, globals instead of modules (the tests have to load files through `node:vm`), and game rules split between `index.html` and `strategy.js`; there is no type checking, no component reuse, no staging site (a push to `main` goes live), and the tests use a stub DOM, not a real browser.
**What would change my mind:** A PRD change that needs data to leave the device, such as cross-device history, instructor-visible metrics, or accounts (now Won't W6), or UI state grown complex enough through F5–F8 (summary, rationale, house rules, a second variant) that hand-written DOM updates in one file become the main source of bugs.
